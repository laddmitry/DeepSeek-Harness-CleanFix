# Изменения и причины

## Очистка каналов DeepSeek

В рабочей конфигурации отключены и запрещены при admission: провайдеры/аккаунт DeepSeek, фирменный поиск, отправка журнала сессии и inventory, telemetry/exporters, product analytics и динамические API extensions. Ограничение проверяет manifest и aliases до импорта и действует в Web/headless/SDK/ACP. Настройки аккаунта и account-controller отключены в Web. Часть определений пакетов остаётся в исходниках и dependency graph; это не работающий вход в аккаунт.

В CLI исходящий Node TCP разрешается только к выбранному literal host/port локального модельного сервера. По умолчанию это 127.0.0.1:11434. Публичные адреса, произвольные DNS-имена, прокси и переход на другой порт не разрешаются. В Web запрещены внешние connect/img-источники; сохранён CSP с nonce без unsafe-eval. Доступ — локальный launch token, обмен на подписанную cookie и redirect на адрес без токена.

## Исправления прежней очистки

| Затронутая функция | Исправление |
|---|---|
| SDK и ACP были заблокированы launcher | Восстановлены четыре профиля и их проверяемые композиции |
| SDK/ACP могли выбирать DeepSeek default или незаметно монтировать adapter | Локальные defaults в CLI, TypeScript, Python и ACP; сервер требует явно зарегистрированный adapter |
| Конфигурации и overlays не применялись | Восстановлены слои profile/home/argv; запреты пакетов и telemetry действуют после overlays |
| Локальные настройки, permissions, инструкции и skills были отключены | Восстановлены; обход инструкций/skills останавливается на границе файлового провайдера |
| Permissions зависели от отключённого shell | Используют sandboxPolicy; разрешены read-only/workspace-write с ask, Auto/full-access запрещены |
| Worker/sandbox/model могли оставаться в ожидании | Обязательные startup-компоненты приводят к явной ошибке при отказе |
| Web мог ломаться из-за CSP и JS evaluator | Исправлены assets/nonce и отложенная компиляция конфигурационных выражений |
| Windows-поставка не совпадала с layout pnpm deploy | Исправлен поиск CLI, разрешение физического пути для ACL canary и комплект dependency closure |

Модель по умолчанию — Ollama Qwen3:0.6b, context 8192, max output 2048, reasoning_effort none. Адрес, имя и лимиты локального backend можно задавать через Run-Harness.ps1; изменять действительный контекст Ollama нужно согласованно. Локальная история и foreground spawn/fork сохранены.

## Подготовка публичного комплекта

Удалены устаревшие лабораторные инструкции, host-path provenance и прежние отчёты публикации. Вместо них созданы эти документы. Сохранены исходники, тесты и лицензии. Автоматическая отправка в GitHub не выполняется.

Из runtime убраны build-only метаданные pnpm и неиспользуемые .bin-обёртки с абсолютными путями. Корневые dependency metadata сделаны переносимыми. В клиентском JS изменены только region-комментарии с путями сборщика; проверено равенство остальных байтов JS. Перечень преобразований с SHA-256: [runtime-transformations.json](../../deploy/runtime-transformations.json). Результирующий архив проверяется заново, а не наследует PASS от прежнего архива.

Установщик универсален для описанной чистой Windows 11 Pro: не требует имени старой VM или файла пароля из переписки. Пароль DSHAudit вводит установщик, worker получает случайный пароль. Первый рабочий вход добавляет обе раскладки и ярлык. Offline payload включает все runtime-зависимости; компоненты собираются из 33 частей с SHA-256.

Сохраняющиеся запреты и незавершённые проверки перечислены в [границах безопасности](SECURITY_RU.md) и [результатах](TEST_RESULTS_RU.md).
