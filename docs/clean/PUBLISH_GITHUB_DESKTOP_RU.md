# Публикация через GitHub Desktop

## Подготовленный локальный репозиторий

Используйте папку DeepSeek-Harness-Clean-20261015, указанную в локальном отчёте передачи. У неё новая история и ветка main. Старые публикационные папки не являются этой версией. В подготовленной папке уже будет локальный проверенный коммит; повторно создавать репозиторий и первый коммит не требуется.

1. В GitHub Desktop выберите File → Add Local Repository → Choose, укажите подготовленную папку и нажмите Add Repository.
2. Проверьте Current Repository и main. Changes должно показывать No local changes. В History выберите последний коммит и Copy SHA. Сверьте полный SHA с локальным отчётом передачи. Любые изменения до публикации требуют новой проверки версии.
3. Нажмите Publish repository **самостоятельно**, когда готовы. Выберите новое свободное имя публичного репозитория и снимите Keep this code private. Публикация существующего старого remote и force-push этой инструкцией не предусмотрены. Подготовка не создаёт remote и ничего не отправляет на GitHub.
4. Дождитесь отправки всего комплекта: payload занимает около 961 МБ. Git LFS и дополнительные release assets не нужны; каждый файл payload меньше 50 MiB. Не исключайте части payload ради уменьшения push.
5. Откройте Repository → View on GitHub, затем нужный коммит. Для сдачи скопируйте **URL конкретного коммита** вида https://github.com/OWNER/REPOSITORY/commit/FULL_SHA. Убедитесь, что FULL_SHA совпадает с проверенным SHA. Ссылка только на ветку main не фиксирует версию.
6. Откройте этот commit в браузере и убедитесь, что README, docs/clean и все части payload присутствуют. Код можно скачать ZIP именно по коммиту. Если позднее создадите релиз, направьте его tag на тот же коммит.

Публичная ссылка появляется только после вашего push. Локальная подготовка не выдаёт непроверенный URL за уже опубликованную версию.

## Проверка перед публикацией

Проверены файлы и новая история, а не только .gitignore. В сообщении передачи находятся полный SHA, результаты VM-проверки и контрольные суммы. Имя и адрес commit-автора технические, личный email не используется. В отчёте проверки нет самих найденных или проверяемых секретов.

Если вы внесли изменения, повторите проверку исходников/payload и рабочие тесты. Опциональные developer-утилиты Python находятся в deploy; для установки на чистой Windows Python не нужен.

Официальные инструкции: [добавить локальный репозиторий](https://docs.github.com/en/desktop/adding-and-cloning-repositories/adding-a-repository-from-your-local-computer-to-github-desktop), [публикация локального репозитория](https://docs.github.com/en/desktop/adding-and-cloning-repositories/adding-an-existing-project-to-github-using-github-desktop), [лимиты файлов](https://docs.github.com/en/repositories/working-with-files/managing-large-files/about-large-files-on-github).
