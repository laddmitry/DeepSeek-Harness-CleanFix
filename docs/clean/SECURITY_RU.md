# Безопасность и ограничения

## Что обеспечивает эта конфигурация

Активные каналы DeepSeek отключены и запрещены admission-проверкой. Web не предлагает вход в аккаунт DeepSeek и использует локальный token/cookie. Node TCP в CLI ограничен адресом и портом выбранного локального LLM backend; журнал содержит адрес/порт и решение, а не тело запроса. Ollama настроена на loopback с отключённым cloud. Установка не скачивает файлы.

DSHAudit и DSHAgent — обычные локальные пользователи Windows. Контроллеру выдаются SeAssignPrimaryTokenPrivilege и SeIncreaseQuotaPrivilege для создания ограниченного worker; worker этих прав не получает. Источники, tools и kit доступны на чтение, workspace — на запись. Worker не получает доступ к данным/логам контроллера, кроме предусмотренного private-temp. Credential-файл содержит локальный случайный пароль и хранится вне репозитория под отдельным ACL.

## Границы

TCP-проверка Node не охватывает UDP, произвольный native-код, все дочерние процессы и поведение модельного сервера. Отключённые NIC в тестовой VM исключают внешнюю передачу именно в этом окружении, но отсутствие трафика без NIC не доказывает отсутствие всех попыток передачи. Общая сертификация изоляции и аудит каждой внешней зависимости не заявляются. Для сервера с доступом в сеть требуется отдельная политика ОС/сети.

Shell, terminal, PTC/workflow, внешний MCP/исполняемые bridges, установка плагинов и общий web fetch остаются запрещены. Поэтому это локальный файловый агент с SDK/ACP для внешнего оркестратора, а не все возможности исходного продукта. Действующий контекст разговора передаётся выбранному вами локальному LLM: без него нормальная работа модели невозможна.

Субагенты используют доступный локальный provider; отдельные upstream account/provider-пакеты физически не вырезаны из всего исходного дерева. Наличие их исходников или доменных строк в тестах не означает разрешение загрузки.

## Публикационные данные

Новая локальная история не наследует прежние Git-объекты, reflog или remotes. Проверяются все tracked-файлы, вложенные payload ZIP, все локальные Git-объекты, включая недостижимые, author/committer metadata, сообщения, refs и конфигурация remote. Проверка известных приватных значений выполняется с локальным списком вне репозитория; значения в отчёт не записываются. Отчёт проверки файлов/payload и правила новой истории указаны в [publication-audit.json](evidence/publication-audit.json). Полный SHA локального коммита и итоговая проверка Git-объектов передаются вместе с локальным отчётом публикации; хеш собственного коммита внутрь него не записывается.

Паролей по умолчанию, реальных API-токенов, worker credentials, пользовательских сессий, VM-дисков, unattended answer files и приватных тестовых ISO в поставке нет. Бинарные payload и исходники имеют хеши. Хеши подтверждают совпадение байтов, а не доверенность автора: скачивайте конкретный проверенный commit.

Правообладатели, имена из LICENSE/third-party notices, upstream ссылки и явно синтетические тестовые примеры сохраняются. Это обязательная атрибуция/тестовые данные, а не личные данные оператора этой сборки.
