# Установка на чистой Windows 11 Pro

## Перед началом

Нужна установленная Windows 11 Pro x64, локальный администратор и свободный каталог C:\DSH. Пользователи DSHAudit и DSHAgent ещё не должны существовать. Windows и лицензия ОС не входят в комплект.

Проверяемая конфигурация VM: 2 vCPU, 6 ГБ RAM, динамический диск 80 ГБ, EFI, TPM 2.0, Secure Boot. Отведите не менее 10 ГБ свободного места сверх установленной ОС для репозитория, runtime, модели, кэша и логов. Модель работает на CPU, GPU не требуется. В изолированном тесте все NIC, общий буфер обмена и drag-and-drop отключены; Windows ISO установлен отдельно.

Рекомендуем сначала использовать отдельную VM. Для проверки без внешней сети отключите адаптеры именно этой VM в VirtualBox. Комплект самодостаточен после скачивания; установка не обращается к registry или серверу моделей.

## Установка

1. Скачайте ZIP проверенного коммита целиком либо клонируйте его через GitHub Desktop. Распакуйте в короткий локальный путь, например C:\HarnessClean. Не запускайте из окна ZIP или сетевой папки. Папки deploy и payload должны находиться рядом с INSTALL.cmd.
2. Откройте INSTALL.cmd. Подтвердите запрос администратора Windows. Стартовый скрипт снимает отметку скачанного файла только с собственных deploy-скриптов; глобальная execution policy не меняется.
3. В окне установщика задайте **свой пароль DSHAudit**. Готового пароля в репозитории нет. Второй пароль для DSHAgent генерируется случайно и сохраняется в защищённом credential-файле.
4. Дождитесь сообщения Installation complete. Проверка частей и применение ACL занимают время; не закрывайте окно во время обработки каталогов. Установщик создаёт C:\DSH, ставит отдельную PowerShell 7 и Node, распаковывает runtime/модель и назначает права двух обычных пользователей. При наличии другой версии Node в C:\Program Files\nodejs установка откажется её перезаписывать.
5. Выйдите из установочного администратора и войдите в Windows как **DSHAudit** с выбранным паролем.
6. Откройте **Harness-First-Run** на рабочем столе. Он настроит английскую US и русскую раскладки, проверит ACL и создаст личный ярлык **Harness-Local**. Переключение языка — Win+Пробел; при необходимости выйдите и снова войдите в DSHAudit. UAC для рабочего запуска не нужен.
7. Дождитесь запуска Ollama и Harness. Если браузер не открылся, скопируйте из окна строку после dsh web: целиком, включая токен, и откройте её в браузере той же Windows/VM. Аккаунт DeepSeek не требуется. Окно Harness оставьте открытым.

Установщик рассчитан на один чистый запуск: существующие данные и аккаунты не сбрасываются. При ошибке сохраните сообщение и логи, а для новой попытки восстановите чистый снимок VM. C:\DSH автоматически не удаляется. Ручное применение исправлений к частичной установке не входит в обычный путь.

## Проверка результата

Отправьте: «Создай hello.txt с текстом LOCAL_HELLO, затем прочитай файл и покажи содержимое». Проверьте сам файл в C:\DSH\workspace. Первый запрос небольшой CPU-модели может выполняться заметно дольше последующих. Текст ответа без файла и события инструмента не считается доказательством выполнения.

Повторный запуск: **Harness-Local**. Он поднимет Ollama с loopback и OLLAMA_NO_CLOUD=1, если своего процесса ещё нет. Чужой процесс на порту 11434 не принимается автоматически: сопоставляются PID, путь и адрес listener.

Рабочие файлы: C:\DSH\workspace. Логи и JSONL попыток TCP: C:\DSH\logs. Приватные данные контроллера: C:\DSH\data. DSHAgent не предназначен для ручного входа.

## Автоматическая проверка

Под обычным DSHAudit откройте C:\DSH\tools\PowerShell7\pwsh.exe и выполните:

```powershell
& 'C:\DSH\kit\Run-Verification.ps1'
```

Она проверяет настройку профиля, шесть сквозных сценариев, а также реальную Ollama. Итог: C:\DSH\logs\verification-latest.json; подробности лежат в указанной там папке. Это инструментальные и протокольные smoke-тесты, а не полный исходный suite. Состав и границы описаны в [результатах](TEST_RESULTS_RU.md).

## SDK и ACP

Под DSHAudit доступны профили sdk и acp через C:\DSH\kit\Start-LocalHarness.ps1 с параметром -Profile. Они используют stdio JSON-RPC/ACP. Внешний оркестратор должен запускать очищенный CLI под этим пользователем и использовать локальную модель. Примеры модифицированного SDK: [TypeScript](../../packages/sdk/client/README.md), [Python](../../python/sdk/README.md). Публикуемый upstream npm/pip-пакет не подменяет эту очищенную поставку; явно задавайте путь к очищенному CLI.
